Statutory company operations, from contract to payroll close

The statutory work of running a company in Korea, carried end to end from one sentence, without the person needing to understand the work.

Employment contracts, payroll close, the four social insurances and statutory-obligation decisions are the first scope. This is not an HR/payroll service, and not an ERP with a chatbot on it. The language model is the most replaceable part here; what is not replaceable is five things — the compliance ruleset, the company graph, the transactional workflow, the government and banking integrations, and the evidence ledger.

The discipline sits in code as ten invariants. The model does not calculate. Screen, API and agent tool are one and the same thing, and a test checks that they agree. Calculations are pure functions with no I/O and no clock; money is decimal, not floating point; a calendar date and an instant are different types. Statutes and rates are not code but rulepack data carrying an effective date and a source.

A human opens anything irreversible. Without an approval token it is refused, and evidence is an append-only hash chain — the database role has no update or delete permission at all. The boundary where a licensed tax or labour professional must judge is owned by the type system, so that area is never exposed as an agent tool. When the thing that blocks is a type rather than a rule, there is no way around it.

The current state, stated plainly. The foundation, the isolation, the conversation loop and tool parity are done. But hiring registration, which passes as a short sentence, does not surface on the tool surface when the real utterance carries a name, a date and an amount. The cause was domain ranking, not budget — raising the limit from 42,000 to 70,000 turned failures into passes, which is how the budget hypothesis was discarded. This paragraph changes when that is fixed.
