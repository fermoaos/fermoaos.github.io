How not to believe an agent’s “done”

For anyone about to hand real work to an agent. The short version: the point where an agent says it is finished and the point where the work is actually finished are not the same place. We close that gap with code rather than with human attention.

Sep 10, 2026

0.925 was not performance, it was leakage

We trained a repurchase propensity model. Holdout AUC 0.925. Normally you ship that and move on. Then we put an untrained one-line frequency rule against the same holdout and it scored 0.880. Training was buying us 0.044.

Digging into why gave us the answer. The model had not learned who buys; it had learned how many orders a customer has. The top features by gain were orders in the last 365 days at 42.3% and spend at 19.0%. It was reading back a hidden constant the synthetic generator had fixed before it made the data. The high score was evidence of leakage, not of skill.

So we do not sell that model. The wiring is all there, but the default path is the rule and the model is marked non-authoritative. The decision is written into the bakery case on this site.

The real problem was that nobody had measured the baseline

The same investigation turned up something far more uncomfortable. The rule the store was actually running, which ranks customers by whether their personal purchase cycle has come due, scored AUC 0.284. That is worse than the 0.5 you get from guessing. The top 10% it selected repurchased at 0.287 times the overall average, meaning targeting with it produced a list 3.5 times worse than picking at random.

The cause was almost disappointingly simple. In this data, a long gap since the last order does not mean due to buy soon; it means this person rarely buys. The subscribers who were certain to buy next month had short cycles and had therefore always bought recently, so the due-date rule was pushing them to the bottom of the list.

This does not make the rule useless. For its original job, deciding when to send a reminder, it still holds. It simply must not be used to rank repurchase probability, and the only thing that revealed that was standing up a fair opponent and measuring both with the same ruler. Work that set out to validate a model ended up catching the rule that was already running.

A tool passing you usually means it answered a different question

Accessibility had the same shape. This site runs axe across every page in both themes and holds violations at zero. Meanwhile the keyboard focus ring in the light theme was highlighter yellow, and against the paper background its contrast was 1.22 to 1. WCAG 2.2 asks for 3 to 1. A focus indicator that was effectively invisible sat there while the checks stayed green.

axe was not broken. Focus-indicator contrast is simply not something axe looks at. The mistake was reading a tool’s silence as safety. The gate now reads the computed values out of the browser, measures the contrast itself, and fails below 3 to 1. After fixing it we deliberately reverted the CSS to confirm the gate really does catch 1.21 to 1 and fail, because a gate you have never seen fail is not a gate.

Gates lie too

Once you start trusting gates, the gates become the next trap. Our demo dock checker had the number four hardcoded as the scenario count. The moment we grew to seven scenarios, a perfectly healthy build failed its check. The day before, the accessibility checker had a renamed page path baked in and spent thirty seconds knocking on an address that no longer existed. The same defect twice in two days.

Both now derive their numbers from data. The scenario count is known by the manifest, the page list is known by the disk, and a missing path dies loudly instead of passing quietly. When you write a new gate, any constant you see in it is where the next false verdict will come from.

The cheapest lesson deserves recording too. If you pipe a command’s output through something to trim it and then print the exit code, that code belongs to the trimmer, not the command. We read it as a pass, and it had read nothing at all.

The three lines we keep

Code owns the verdict. Not the model, not the agent, not the person; nobody grades their own output. Passing is an exit code, not somebody’s sentence.

Every treatment gets a fair control. A trained model is measured against the untrained rule, and a new method against the one currently running, on the same ruler. A number with no control says nothing, however large it is.

Gate constants are derived from data. And once a gate exists, break it on purpose once. A gate you have never watched fail does not prove that anything passed.
