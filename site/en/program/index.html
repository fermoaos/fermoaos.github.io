AI Fabric

Twenty-five pieces for a device manufacturer

Assume one company builds the phones, the appliances, the robots, the fabs and the base stations. What has to exist before agents can run on top of that? We laid it out as twenty-five pieces. This is our own reference program, not a customer's brief.

Six of the twenty-five have running code behind a gate. The other nineteen are design and scaffolding. Each item says which.

A. Tokens and inferenceB. Personalization and privacyC. Agent platformD. Identity, payment, commerceE. Enterprise and fleetF. Home and robotsG. Manufacturing, radio, verification

A Tokens and inference 5

The path every request takes, and the destinations that path can choose. The precondition for the other six bundles.

  • 01running code, gated

    AI router — the token control plane

    Not a model, a control plane. Owning the path every request takes is the precondition for the other twenty-four.

    One OpenAI-compatible internal endpoint. Each request is judged against SLO and privacy class to pick on-device, private cloud or an outside frontier model, falls back on failure, and meters tokens per feature and per org.

    Attribution ledger and counterfactual costing, with gates G1–G7 deciding by exit code. Request schema and all three routes wired, 22 of 22 end-to-end tests passing.

  • 02design stage

    Skill distillation factory

    Finding the narrow work a large model keeps repeating and pushing it down to a small one — done by a pipeline, not a person.

    Cluster repeated tasks out of the router ledger, collect teacher traces, synthesize data, then distil, gate, quantize, benchmark on device and ship. Every stage passes on a gate, not on judgement.

  • 03design stage

    Model optimization platform

    Compete with quantization researchers and you lose. The layer that selects among their results is empty.

    A developer states targets only — under 1% accuracy drop, under 50ms latency, under 500MB, on two mobile SoCs. The platform sweeps the grid and picks the point.

  • 04design stage

    Device-first inference SDK

    Every call that lands on the device costs nothing to serve. A hyperscaler cannot match that price.

    One line: the task, a privacy class, a latency ceiling, a cost ceiling. The router reads what the device can do and picks on-device, edge or cloud — and only what actually reached the cloud is billed.

  • 05design stage

    Edge token POP

    Turn a carrier edge site into a token point of presence rather than a content one.

    Put the inference runtime on carrier MEC to create a middle tier between device and cloud. It becomes the router's third destination, and a new revenue line for the carrier.

B Personalization and privacy 4

Personalize without shipping personal data to a server. What you sell is not the prediction — it is the guarantee that the raw data never left.

  • 06design stage

    Private audience engine

    Offer to predict purchase intent and you will be told they already do. What is missing is a contract that the raw data never leaves.

    A small on-device model turns app use, search context, purchases, time and coarse location into a vector. Only a coarse segment token, a confidence interval and a TTL go to the server. There is no per-event upload and no per-user ad request.

  • 07design stage

    Federated attribution

    Move only the targeting into privacy and advertisers will not buy. Measurement has to move with it.

    The difference is where the join happens. A clean room joins on a server; this joins impression and conversion inside the device and sends up only the aggregate. Linking a TV impression to a mobile conversion in one household also stays local.

  • 08running code, gated

    Personal AI memory

    The most defensible asset of the agent era — and few companies can extend it past the phone.

    Phone, watch, PC, TV, car, appliances and robots all write to one personal memory graph. The hardware security layer encrypts it; the user owns it. Outside agents do not copy the memory — they send a scoped question and receive only an answer.

    All seven ownership properties gated and passing: scope, canary, revoke, delete, export, plane separation, audit. The gate is itself mutation-tested against three ways of escaping scope — prefix match, case folding and pattern match — and catches all of them.

  • 09design stage

    Personal adapter delivery

    Not the same model for everyone. A base plus a personal adapter.

    Personal data never leaves; only the adapter trains and merges on the device, and the server does not see the adapter either. Change phones and the adapter follows, still encrypted.

C Agent platform 3

What the shift from apps to skills needs: somewhere to publish, something to judge permissions, and a way to bring existing software across.

  • 10design stage

    Agent and skill store

    The store for the moment the unit of installation stops being an app and becomes a skill. Long term it can be bigger than the router.

    A registry for skills, tools, workflows and model adapters. The hardware security layer vouches for signatures and permission scopes, and permissions are shown to the user the way app permissions are. Billing follows calls; quality is decided by a regression gate.

  • 11design stage

    Agent execution governance

    If you cannot answer whose authority an action was taken under, agents stop at the first incident.

    Actions arrive as an intermediate representation, get classified by risk, and code decides between auto-run, ask-for-approval and refuse. Approval binds to a plan id, so changing the plan voids the old approval; a refusal cannot be opened by an approval. Every execution lands in a tamper-evident ledger with a rollback path.

  • 12design stage

    Legacy apps into agents

    The supply side of the store. Nobody is going to rewrite hundreds of thousands of APIs and apps.

    Take an existing interface and generate the skill manifest, permission declaration, tool schema, evaluation set and UI card; a human only reviews. This is where the store's opening catalogue comes from.

D Identity, payment, commerce 4

Before an agent spends on your behalf, the delegation — and its revocation — has to be guaranteed in hardware.

  • 13design stage

    Presence identity

    Replace authentication that leans on one face with a combination of device, wearable, proximity, behaviour and cryptographic identity.

    Stage one opens no wallet at existing terminals. Stage two makes a watch or ring an authentication factor. Stage three uses ultra-wideband to confirm presence at the till. The point is that no payment data crosses that radio — it confirms presence, and the payment stays on the existing rails.

  • 14design stage

    Agent-delegated payment

    China shipped five of these in the first half of 2026. Korea has none yet.

    A rail for delegating payment authority to an agent, bounded by limit, period, merchant and category. Hardware vouches for the delegation certificate, the user can revoke at any time, and every use lands in a ledger. At that point the wallet stops being a wallet and becomes trust infrastructure.

  • 15design stage

    Trust agent

    The most executable of the twenty-five. Both halves already exist; only the line between them is missing.

    Put graduated friction on transfers and payments that happen while a call scores as high risk — a warning, a delay, a second factor, a note to family. The judgement runs on device and the call content never leaves.

  • 16design stage

    Agentic commerce network

    Not being a search-ads company is exactly why the transaction layer is reachable.

    The agent takes the user's constraints — budget, deadline, conditions — negotiates against seller agents and carries through to payment. The position to hold is not which storefront wins; it is the rail the transaction crosses.

E Enterprise and fleet 2

Low technical difficulty, high organizational difficulty. Start with what rides on contracts that already exist.

  • 17running code, gated

    Enterprise private AI

    Low technical difficulty, high organizational difficulty. Rating it most feasible is overrating it.

    From a managed device through the security layer to an AI gateway, and on to private AI inside the company — on-prem GPUs or a designated cloud. The enterprise sets its own routing, policy and audit.

    A minimal RAG doing real inference against an in-house GPU endpoint, six decision gates, and a gate that checks the gates — all passing on live runs.

  • 18design stage

    Autonomous device fleet ops

    One of the few items that rides on existing contracts without a new one. The easiest internal approval in the set.

    "Battery drain is up 18% since last week" gets an answer: read the telemetry, find the app version, identify affected devices, draft a policy, roll it out in stages. Device management becomes autonomous operation — and every rollout passes an approval gate.

F Home and robots 2

A home is both a compute pool and a state representation. On a robot, approval and rollback stop being convenience and become safety requirements.

  • 19design stage

    Cross-device compute fabric

    A home is a compute pool and a state representation. Two faces of one problem, so they ship together.

    A scheduler places inference by privacy, latency, battery and heat. Device telemetry infers the layout of the space and the rhythm of the household, so an agent declares a goal instead of calling appliances one at a time.

  • 20running code, gated

    Robot skill OS

    Not motor control — a control plane and a data loop. And the manufacturer is its own first customer.

    The control plane covers model serving, mission planning, a skill registry, telemetry, fleet, evaluation and rollout. The data loop captures failure episodes, classifies them, replays them in simulation, synthesizes variants, retrains, evaluates and ships. On a robot, approval and rollback are safety requirements.

    Six physical-safety envelope checks run as a gate. Verified on synthetic fixtures only — no real robot or simulator is wired in yet.

G Manufacturing, radio, verification 5

The areas where proven methods already exist — plus the ruler that judges a vendor against a cheap baseline before you buy.

  • 21running code, gated

    Fab and field scheduling

    Manufacturing at world scale, and the rosters are still built by hand in a spreadsheet. One of the few items with a proven method behind it.

    A constraint-programming scheduler. Hard constraints — statutory rest, qualifications, equipment compatibility — are gates; soft preferences like requested shifts and continuity go in the objective. Re-planning around an absence minimizes change instead of starting over.

    Measured against eight instances of a public nurse-rostering benchmark, with five axes deciding by exit code: gap, feasibility, reproducibility, time budget and baseline. The deliverable is a ruler before it is a scheduler.

  • 22design stage

    RF fingerprinting and a radio closed loop

    A company that sells network equipment, and the physical-layer RF assets were missing from the proposal entirely.

    Two axes. On the network side, RF fingerprinting, modulation classification and interference separation ship as open-RAN control apps and the effect is measured in a closed loop. On the manufacturing side, the same signal-processing stack detects RF anomalies in equipment. One codebase, two business units.

  • 23running code, gated

    Procurement proof gate

    Before you buy AI, code decides whether it beats something you built in a week. The cheapest item to start and the fastest to save money.

    For each candidate task, build a cheap baseline automatically — rules, statistics, a co-occurrence table — and measure the vendor model with the same ruler. If it does not win, it does not get adopted. The verdict is an exit code, not an opinion.

    All seven axes implemented: baseline validity, same ruler, statistical significance, headroom, claim coverage, determinism and budget honesty. Fourteen gate self-tests and twenty-four tests passing.

  • 24design stage

    Vision event ledger

    The problem with video AI is not accuracy, it is unit cost. A cheap prefilter and amortizing once per piece of content is the answer.

    Two stages. A CPU prefilter discards most frames; only what survives reaches the vision-language model. Results land in an event ledger, so each piece of content is analyzed once and per-user work is only re-ranking. Cost scales with content, not with users.

  • 25design stage

    Model safety instrumentation

    Run several models side by side and there is no tool that measures what each one refuses — or what the refusal cost in capability.

    Measure the causal geometry of refusal. The headline is not a refusal rate but capability delta, distribution divergence, the number of intervened parameters, and a causal interaction graph. It separates out how much safety cost in capability.

Which piece should we start with?

Six already run behind a gate. The rest get built the same way.
